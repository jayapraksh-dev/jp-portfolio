# Portfolio Project Instructions

## Project

This project is a React migration of an existing HTML portfolio.

The original HTML reference is located at:

`reference/portfolio.html`

## Primary Rule

The reference HTML is the visual source of truth.

The first objective is to reproduce the existing portfolio in React without unauthorized redesign.

## Technology

Use:

* React
* Vite
* JavaScript
* JSX
* Tailwind CSS
* Lucide React

Do not use TypeScript unless explicitly requested.

Do not add unnecessary dependencies.

## Reference HTML

Never modify:

`reference/portfolio.html`

unless the user explicitly asks for it.

Use it as a reference when implementing or reviewing components.

## Development Approach

Work incrementally.

Do not migrate the entire application in one step.

Preferred order:

1. Project foundation
2. Navbar
3. Hero
4. Skills marquee
5. About
6. What I Do
7. Tech Stack
8. Projects
9. Project filtering
10. Contact
11. Footer
12. Full integration
13. Testing
14. Deployment

After each meaningful step:

1. Implement.
2. Run the application.
3. Test the affected functionality.
4. Check the browser.
5. Explain the important changes.
6. Commit the working state when appropriate.

## Design

Preserve the existing:

* Colors
* Typography
* Layout
* Spacing
* Responsive behavior
* Animations
* Interactions
* Dark/light theme
* Cards
* Buttons
* Navigation
* Project filters

Do not redesign components unless the user explicitly requests a redesign.

## Beginner-Friendly Code

The user is learning React.

Prefer code that is:

* Clear
* Simple
* Explicit
* Easy to read
* Easy to modify

Avoid unnecessary abstractions.

Explain important React concepts after meaningful implementation tasks.

## Changes

Keep changes focused.

Do not modify unrelated components.

Do not refactor the entire application while implementing a small feature.

## Dependencies

Before installing a new dependency:

1. Check whether the existing stack can solve the problem.
2. Explain why the dependency is needed.
3. Ask for approval when the dependency is not clearly necessary.

## Testing

Do not claim a feature is complete merely because the code compiles.

Verify the affected behavior in the browser whenever possible.

Always consider:

* Mobile
* Tablet
* Desktop
* Dark theme
* Light theme
* Interactive states

## Learning

When the user asks "why", explain the concept instead of simply changing the code.

The goal is not only to build the portfolio.

The goal is for the user to understand how the React application works.
